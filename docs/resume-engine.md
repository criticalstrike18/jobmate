# JobMate — Multi-Format ATS Resume Engine Specification

## 1. Core Principles: 100% ATS-Compliant Across All Formats

ATS parsers (Workday, Greenhouse, Lever, Taleo, iCIMS) parse documents linearly. To guarantee zero parsing failures, every resume generated by JobMate conforms to the **Universal ATS Standard**:

1. **Strict Single-Column Flow**: No multi-column tables, sidebars, floating text boxes, or overlapping layers.
2. **Standard Section Hierarchy**: Only recognized header titles (`Technical Skills`, `Professional Experience`, `Projects`, `Education`).
3. **True Vector Text Layer**: No rasterization, no flattened SVG text, no icons as bullet points.
4. **Universal Standard Typography**: Calibri, Arial, Helvetica, or Times New Roman equivalents with clean UTF-8 bullet points (`•`).
5. **Machine-Readable Metadata**: Standard date notation (`Month YYYY` or `YYYY - Present`) and clean hyperlink styling.

---

## 2. Multi-Format Output Architecture

Instead of designing separate document templates for each format, JobMate uses a **Canonical Resume Schema (JSON)** as the single source of truth. Specialized format compilers transform this JSON into:
* **PDF (`.pdf`)**: Native vector PDF with 1-page budget enforcement.
* **Microsoft Word (`.docx`)**: Native Office Open XML (OOXML) document using standard paragraph styles.
* **Plain Text / Markdown (`.txt` / `.md`)**: For copy-pasting directly into unstructured ATS text areas (e.g. Workday).
* **JSON Resume (`.json`)**: Open-standard format for data portability.

## 3. The Canonical Resume Schema (`ResumeDocument`)

```typescript
export interface ResumeHeader {
  fullName: string;
  email: string;
  phone?: string;
  location?: string;
  links: Array<{ label: string; url: string }>;
}

export interface SkillCategory {
  category: string; // e.g. "Languages", "Frameworks & Systems", "Cloud & Tools"
  skills: string[];
}

export interface ExperienceItem {
  company: string;
  role: string;
  location?: string;
  startDate: string; // "Jan 2023"
  endDate: string;   // "Present" or "Dec 2024"
  bullets: string[];
}

export interface ProjectItem {
  title: string;
  headline?: string;
  techStack: string[];
  link?: string;
  bullets: string[];
}

export interface EducationItem {
  institution: string;
  degree: string;
  field?: string;
  graduationDate: string; // "May 2022"
  gpa?: string;
}

export interface ResumeDocument {
  header: ResumeHeader;
  summary?: string;
  skills: SkillCategory[];
  experience: ExperienceItem[];
  projects: ProjectItem[];
  education: EducationItem[];
}
```

## 4. Format-Specific Compilers

### 4.1 Microsoft Word Compiler (`.docx`)
* **Technology**: `docx` (npm library, zero binary dependencies, runs on both Node.js backend and client browser).
* **ATS Optimization**:
  * Uses semantic heading levels (`Heading 1`, `Heading 2`) so ATS software detects section boundaries natively.
  * Uses standard `ListParagraph` bullet styles instead of manual character spacing.
  * Embeds clickable hyperlinks on project titles and GitHub links without breaking Word's XML parser.

```typescript
// Sample Word Compiler snippet using docx
import { Document, Paragraph, TextRun, HeadingLevel, AlignmentType } from 'docx';

export function compileToWord(resume: ResumeDocument): Document {
  return new Document({
    sections: [{
      properties: {
        page: {
          margin: { top: 720, bottom: 720, left: 720, right: 720 } // 0.5-inch margins (in twips)
        }
      },
      children: [
        // Name Header
        new Paragraph({
          alignment: AlignmentType.CENTER,
          children: [
            new TextRun({ text: resume.header.fullName, bold: true, size: 36, font: 'Calibri' })
          ]
        }),
        // Contact Links
        new Paragraph({
          alignment: AlignmentType.CENTER,
          children: [
            new TextRun({
              text: `${resume.header.email} | ${resume.header.phone || ''} | ${resume.header.location || ''}`,
              size: 20,
              font: 'Calibri'
            })
          ]
        }),
        // Section: Technical Skills
        new Paragraph({
          text: 'TECHNICAL SKILLS',
          heading: HeadingLevel.HEADING_2,
          thematicBreak: true
        }),
        ...resume.skills.map(s => 
          new Paragraph({
            children: [
              new TextRun({ text: `${s.category}: `, bold: true, font: 'Calibri' }),
              new TextRun({ text: s.skills.join(', '), font: 'Calibri' })
            ]
          })
        ),
        // Section: Experience & Projects...
      ]
    }]
  });
}
```

### 4.2 PDF Compiler (`.pdf`)
* **Technology**: `@react-pdf/renderer` (or server-side `pdfkit`).
* **ATS Optimization**:
  * Emits true Type 1 / OpenType fonts with embedded glyph mappings for 100% extractable text.
  * Implements strict vertical spacing budget (720 points vertical limit) to ensure it fits on **exactly 1 page**.

## 5. Export Endpoint & Client Capabilities

### 5.1 REST Endpoint Contract
* **Route**: `POST /api/resume/export`
* **Query Parameter**: `?format=pdf|docx|txt|json`
* **Payload**: `ResumeDocument` JSON object
* **Headers**: `Content-Type: application/json`
* **Response**:
  * For `format=pdf`: `Content-Type: application/pdf`, `Content-Disposition: attachment; filename="resume.pdf"`
  * For `format=docx`: `Content-Type: application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `Content-Disposition: attachment; filename="resume.docx"`
  * For `format=txt`: `Content-Type: text/plain`, `Content-Disposition: attachment; filename="resume.txt"`

### 5.2 Zero-Cost Client-Side Generation
Because both `@react-pdf/renderer` and `docx` run natively in the browser via JavaScript, the frontend can **also generate all three formats directly in the client** with zero server latency and zero hosting costs. The server endpoint acts as an API fallback.
